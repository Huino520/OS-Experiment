# OS\-Experiment 操作系统实验合集说明文档

本仓库整理了操作系统课程的全部基础运行环境与8个完整实验代码，所有代码均经过调试，可直接正常运行。下文将详细介绍项目目录结构、各实验测试方法及预期运行结果，并附上个人完整实验感悟。

## 一、目录结构说明

- **oslab**：基础运行环境，为经典 Linux 0\.11 原生环境代码，包含配套运行脚本与完整源码，未经过编译，是所有实验的基础依赖环境。

- **exp1**：实验1——操作系统引导机制实现

- **exp2**：实验2——系统调用实现，包含 Step1、Step2 两阶段完整实验代码

- **exp3**：实验3——进程运行轨迹的跟踪与统计

- **exp4**：实验4——信号量的实现与应用（PV操作、生产者消费者模型）

- **exp5**：实验5——地址映射与内存共享。实验主要功能已完成，实现思路与官方参考代码存在差异（未使用休眠队列），整体实现较为粗糙，存在一定局限性。

- **exp6**：实验6——终端字符显示控制功能实现

- **exp7**：实验7——Proc 虚拟文件系统的设计与实现

- **exp8**：实验8——Linux 0\.11 交换分区与全局页面置换实现。基础置换功能可正常运行，但用户态页面置换的部分边界场景未完善，存在功能缺陷。

## 二、测试方法与预期结果

**通用说明**：本项目大部分实验代码已提前编译，无需重复编译，可直接运行脚本测试。

### exp1 操作系统引导

在 `exp1` 目录下执行运行脚本：`\./run`。

**预期结果**：控制台正常打印系统引导提示信息、跳转日志及硬件参数信息，系统正常完成引导。

### exp2 系统调用

- **Step1**：运行脚本进入系统后，执行 `whoami` 命令。预期输出固定姓名 **Jinbo Hu**。

- **Step2**：可通过 `iam` 命令自定义设置用户名，再次执行 `whoami` 可打印当前设置的用户名，系统调用功能生效。

### exp3 进程运行轨迹的跟踪与统计

若需要切换进程调度算法，可修改主目录 `linux\-0\.11/sched\.c` 中 `schedule\(\)` 函数的注释选项，修改后在项目主目录重新编译内核。

进程运行日志可在 Bochs 系统内 `/etc/process\.log` 查看；也可使用 `mount\-hdc` 脚本挂载镜像，在宿主机查看（需提前在 Bochs 内执行 `sync` 同步保存，且需要 sudo 权限）。

**预期结果**：运行 `process\_test` 测试程序后，控制台输出进程正常退出提示，日志文件完整记录各进程的运行轨迹信息。

### exp4 信号量实现和应用

运行脚本进入系统后，依次执行 `pc1`、`pc2`、`pc3` 三组对比测试程序（三组测试需分开运行、单独查看日志）。

生产消费运行日志可通过 `\&gt;` 重定向保存至文件，PV 操作记录默认存储在`/etc/pc\.log`。若需在宿主机查看日志，需先执行 `sync` 同步数据，文件权限不足时可拷贝文件后修改权限再查看。

**预期结果**：控制台正常打印 PV 操作流程、生产者与消费者运行状态，日志文件完整记录对应操作记录。

### exp5 地址映射与共享

进入实验目录后执行`run\.sh` 测试脚本。

**预期结果**：服务端正常启动，间隔一段时间后自动打印共享内存信息。本实验实现存在局限性，仅支持单条信息打印，功能较为基础。

### exp6 字符显示的控制

运行脚本进入系统后，直接测试 **F11、F12** 快捷键对应的字符显示功能即可。

**预期结果**：快捷键可正常切换终端显示模式，功能效果与实验报告表格预期一致。

### exp7 Proc 文件系统实现

运行脚本进入系统后，执行 `run\.sh` 完成测试，脚本会自动生成`info\.txt` 日志文件。

**预期结果**：通过 `vi info\.txt` 查看文件，可正常读取系统进程状态、PID、UID、父进程 ID、打开文件列表等进程详细信息。

### exp8 交换分区与全局页面置换

进入实验目录执行 `run\.sh` 测试脚本。

**预期结果**：控制台正常输出内存页面换出日志、页面置换执行记录，最终打印功能验证成功提示。用户态部分页面置换边界场景尚未完善，存在少量功能缺陷。

## 三、实验感悟与总结

本次操作系统八次实验，让我彻底将课本抽象理论与底层代码的具体实现对应起来。进程调度、信号量机制、内存地址映射、磁盘块管理等原本晦涩、空洞的概念，都有了真实的底层实现支撑，让我直观体会到操作系统软硬件协同设计的复杂性与严谨性。

其中，涉及虚拟地址、物理地址转换与内存置换的实验（实验五、实验八）完成难度最高，也是我掌握最薄弱的部分。地址操作极易出现越界问题，稍有不慎就会污染内核与磁盘镜像，导致系统崩溃，让我深刻认识到底层内存操作的危险性与严谨性要求。

整体来看，大部分实验的调试难度远超预期。单纯依靠人工智能工具很难完成实验，旧版本 Linux 0\.11 内核过于老旧，存在指令缺失、库文件不兼容、环境适配困难等问题，很多细节只能依靠反复调试、查阅源码逐一解决。但每一次功能调试成功后，都会收获极大的成就感，尤其是实验六功能完整实现后，自主完成开发、梳理实现思路的过程，让我收获颇丰。

在实验过程中，我也曾多次为同学讲解实验思路、现场复现实现步骤、分享调试经验。事后反思，这种直接、细致的分享方式存在一定问题，一定程度上剥夺了其他同学独立思考、自主调试的机会，甚至存在违背学术诚信的风险。后续我会调整帮助他人的方式，以思路引导、问题点拨为主，不再直接复刻完整实现过程，尊重每个人的独立实验过程。

同时，我也对课堂实验氛围有了一些思考。整个学期我仅因生病缺席一次实验课，其余时间均全天在实验室调试代码。但实验室整体氛围偏功利，部分同学存在无点名即旷课的情况，学习主动性不足。同时我自身性格偏内向，遇到问题更倾向于独立调试、反复摸索，很少主动请教老师，导致部分实验耗时久、效率低，经常一整天调试却进展缓慢，仅对内核源码逻辑更加熟悉。但也很感谢老师偶尔的交流和指导，让我对学习和未来规划有了一些新的思考。

总而言之，本次操作系统实验是一段非常宝贵的学习经历。我真正理解了操作系统作为“配置在计算机硬件上的第一层软件、对硬件系统的第一次扩充”的核心定位，彻底摆脱了对操作系统的浅层认知。即便未来工作中可能不会直接使用相关底层代码知识，但底层思维、严谨的调试思路、对计算机体系的底层理解，都将是我重要的学习收获。
