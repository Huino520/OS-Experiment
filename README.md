# OS-Experiment
这里整理了实验中使用到的基础环境和完成的8个实验，经过测试可以直接运行，下面将详细介绍目录结构、测试方法和理想结果。

目录结构：

oslab --基础运行环境，经典的linux0.11环境代码，包括常用的脚本和完整的代码，没有经过编译。

exp1 --实验1 操作系统的引导

exp2 --实验2 系统调用，包括两步实验step1和2的实验代码

exp3 --实验3 进程运行轨迹的跟踪与统计

exp4 --实验4 信号量实现和应用

exp5 --实验5 地址映射与共享，完成主要依据参考代码，实现和实验包提示不同（如没有使用休眠队列，完成较为粗糙）

exp6 --实验6 字符显示的控制

exp7 --实验7 proc文件系统的实现

exp8 --实验8 在Linux0.11上实现交换分区和全局页面置换，部分页面置换情况没处理好（集中于用户态的页面置换）

测试方法 & 理想结果：

注意：大部分程序已经经过编译，直接运行即可！

exp1 在主目录（.../exp1/）运行run脚本，即控制台使用./run命令即可。理想输出是打印一段提示信息、跳转提示、硬件参数。

exp2 step1 run脚本进入后运行whoami命令查看系统调用。理想输出是打印固定姓名"Jinbo Hu"；step2 可以用iam命令设置名字，并通过whoami打印当前姓名

exp3 如果希望使用不同调度方法，请修改sched.c中schedule()函数的三选一注释，并在"项目主目录/linux-0.11"重新编译，如果希望查看日志，可以在bochs中"/etc/process.log"中查看，或者使用"mount-hdc"脚本挂载后再宿主机查看（需要sudo，需要再bochs中用sync提前保存，在项目主目录运行）。理想输出是运行process_test后得到进程顺利退出的提示，并且日志中有相关记录。

exp4 run脚本进入后运行pc1、pc2、pc3（实验包要求的三种对比代码，看日志记得分开操作查看），可以正常输出PV操作和生产消耗情况，如果想要在文件中查看，生产消耗记录可以用'>'保存到文件中，PV记录可以在/etc/pc.log查看当前运行的pc记录（注意挂载后查看需要先sync同步，无法查看需要cp到其他地方chmod修改操作权限，需要sudo）。理想输出是可以看到PV操作记录和生产消耗情况记录。

exp5 run脚本进入后运行测试脚本run.sh进行测试。理想输出是服务端启动后隔一段时间打印共享内存信息（目前只支持打印一条信息，局限性很强）

exp6 run脚本进入后测试F11和F12功能就可以了，非常简单的实验，预期结果可以看报告中的表格情况

exp7 run脚本进入后运行run.sh进行测试，运行后得到info.txt，预期结果是使用vi查看info.txt可以看到进程信息，获取状态、打开文件等信息

exp8 run脚本进入后运行测试脚本run.sh进行测试。理想输出是获取到内存块换出信息和验证成功信息

实验感悟：

总的来说，操作系统的八次实验让我更好的将课本知识与具体实现联系了起来，以前虚无缥缈的逻辑概念：进程、信号量、物理块等都有了对应的物理实现，让我深刻感受到了操作系统设计的复杂性，尤其是地址操作，基本上设计地址操作的实验我完成的都不是很好（实验五、八），非常容易越界，甚至会污染磁盘镜像，只能说地址操作确实十分危险而且易错。

就完成感受来说，大部分实验其实完成起来都不容易，纯用AI得到的答案往往是错误的，而且很多时候AI阅读的实验指导总是会忽略一些细节，比如一些小提示，而且linux0.11确实太古早了，很多指令没有、库也不支持，想要实现很多功能都不好实现。不过真的完美实现了真的很开心，我记得实验六完成的时候特别开心，分享给别人实现思路时也很有成就感，只能说苦尽甘来确实胜过一帆风顺。

当然、其中部分实验的实验思路我是进行了分享的，说实话我觉得帮助同学有时是应该的，我不是很擅长拒绝，当然我基本上就是详细讲我是如何实现的，重新再做一遍，事后想想可能不太合适，毕竟剥夺了其他同学自己尝试的机会，我也在分享中慢慢学习如何更好的帮助他人。当然这也可能违背学术诚信，毕竟很多时候我的分享有些直接，虽然是指导为主，不过在别人电脑上重新边讲解边重新做一遍实验似乎并不合适。另外谈到学术诚信、我觉得承认自己的错误并反思是非常有必要的，自我感觉除了实验五和八其余都完成的还是不错的，至于为什么完成的有缺陷我在报告中有分析，老师有耐心可以简单看看。

实验课也让我印象深刻，我只有一次生病没去参加实验，其余实验课时间都在实验室待一天，虽然去实验室会经常迟到十几分钟，不过似乎来的人也非不多，当然我不是在为迟到找借口，只是觉得这种功利性颇强的环境并不好，没有点名就可以随意旷课我是不认同的。当然在实验室我坐一天往往收获却不多，一方面AI太笨了，反复调试实验却总是过不了，经常一天下来毫无收获，就只是对实验涉及那些代码有了深刻的印象。另一方面是我比较内向，并不善于沟通和请教老师，虽然教师就在那里坐着，却还是希望能够自己完成而不麻烦老师，所以和宿舍继续做的效率差不多。不过有一次我早上来的比较早，老师也是问了问我未来的规划，还是挺好的，虽然我对未来也没什么幻想（话说我挺佩服开实验室的人的，这么早就起来，我就起不来）。

一下子废话就说了不少，总之这种吐槽的机会还是不多的。回到正题，还是感谢学校和老师能够提供这次实验机会，让我对位于配置在计算机硬件上的第一层软件，对硬件系统的第一次扩充："操作系统"有了更深刻的认识，虽然未来可能用不上，也算是一段宝贵的经验！
